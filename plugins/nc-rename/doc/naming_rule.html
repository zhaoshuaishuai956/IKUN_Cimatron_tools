文件名格式

示例：03-D10-72 nc.bj　·　04-BNED-07d5-7 nc.bj　·　05-R3-120 nc.bj　·　06-QTECH12-NA nc.bj
序号输出目录内已有最大序号 +1，两位显示；重名自动顺延
刀名XML 的「刀具_夹持」，非法字符清洗后最多 80 字符
最小刀长XML 的「最小有效长度」，向上取整；-1/-2/0 表示无要求，记 NA
后缀空格 + nc + .bj 扩展名（v1 版为无扩展名的空格 + nc）
字段细节

序号

  • 扫描输出目录（TEMP_POST 的上一级）
  • 取 数字- 开头且以 .nc / nc 结尾的最大号
  • 新文件 = 最大号 + 1，格式化为两位
  • 目标名已存在则继续 +1

刀名

  • 来源：程序 XML 的「刀具_夹持」字段
  • 小数点 . 替换为 d（D10R0.5 → D10R0d5）
  • \ / : * ? " < > | 与控制字符替换为 _
  • 连续空白压缩为单空格，首尾去空格与点
  • 取不到时记为 NO_TOOL

最小刀长

  • 来源：程序 XML 的「最小有效长度」
  • 向上取整（Ceiling），例如 71.2 → 72
  • 无最小伸出要求时（Cimatron 记为 -1 / -2 / 0）写作 NA
  • 程序状态必须是「计算完成」才采用
为什么刀长不会再用旧值
✓唯一令牌每次请求生成 GUID，响应必须带同一令牌，杜绝串号
✓程序号比对响应的程序编号必须与 NC 文件里的 PROC 完全一致
✓时间戳新鲜度XML 写入时间不得早于本次请求发起时间
✓SHA256 校验文件内容哈希与插件记录值一致才采信

失败保护（宁可不命名，绝不写错名）

取不到实时 XML、程序号对不上、文件过旧、哈希不一致、最小长度缺失或程序未计算完成 —— 任意一条不满足即放弃重命名：原 NC 文件保持原名不动，同时在输出目录生成 NC_RENAME_FAILED.txt 写明原因。等待超时上限 180 秒。

命名成功后顺带清理

删除 .origins .tools .cycles .msg 以及 print0.txt print00.txt 等后处理附属文件，并自动打开输出目录。

使用方式：插件在 Cimatron 启动时自动加载，全过程无弹窗、无需点击菜单。首次安装或更新后请重启 Cimatron。
排查位置：%USERPROFILE%\NcNamer\auto_service_log.txt（插件取数日志）、post_rename_log.txt（命名日志）、安装备份 backup_时间戳。
